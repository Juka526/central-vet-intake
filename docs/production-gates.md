# 실제 서비스 준비와 다음 개발

이 문서는 개발 준비 목록입니다. 법률 적합성 판정이나 의료적 검증 완료를 의미하지 않습니다. 현재 앱은 localhost에서 가상 데이터만 처리합니다. 실제 배포, 실제 보호자 정보, 외부 AI 전송은 이번 구현 범위에 포함하지 않았습니다.

## 현재 바로 가능한 시험

수의사·접수 담당자가 가상 보호자 역할을 맡아 입력 → 후속 문진 → 위험 안내 → 검토 → 보류/승인 → 복사를 반복합니다. 응급 시나리오에서는 실제 병원에 전화를 걸지 않고 안내가 충분히 빠르고 분명한지 관찰합니다. 병원 명칭 사용 승낙, 실제 대표번호, 원내 연락 절차도 병원 측에서 확인하세요.

위험 항목의 출발점으로 [Merck Veterinary Manual의 응급 안내](https://www.merckvetmanual.com/special-pet-topics/emergencies/evaluation-and-initial-treatment-of-dog-and-cat-emergencies)에 제시된 호흡 이상, 의식·경련, 출혈·외상, 중독, 소변 배출 장애, 고온 손상, 난산 등을 참고했습니다. 이를 한국어 체크리스트·키워드 규칙으로 옮긴 구현은 개발용 해석이며, 임상적으로 검증된 분류기나 병원 프로토콜은 아닙니다.

## 법무·개인정보 검토

병원과 담당 법률·개인정보 전문가가 실제 데이터 흐름을 기준으로 판단해야 합니다. 확인 항목은 수집·이용 근거, 처리자와 수탁자 구분, 병원/개발사 책임, 필수·선택 동의와 거부 시 대안, 음성·자유서술의 식별 가능성, 민감정보 해당 여부, 만 14세 미만 등 보호자 유형, 열람·정정·삭제·철회 절차, 보관기간과 진료기록 해당 범위입니다.

외부 STT/LLM을 추가한다면 수집 항목·전송 국가·하위 처리자·국외 이전·보관기간·모델 학습 사용 여부·삭제 확인·사고 통보·접근권한·위탁계약을 확인하세요. 계약과 설정으로 검증되기 전에는 실제 자료를 전송하지 않습니다. 모델 키는 서버 비밀 저장소에 두고 브라우저에 노출하지 않아야 합니다.

이 도구의 표시·광고와 실제 기능이 진단·처방·의료기기 판단을 유발하는지, 책임 주체와 허용되는 서비스 범위는 별도 검토가 필요합니다. “AI 문진이므로 무조건 허가가 불필요하다”는 전제로 진행하지 않습니다.

개인정보보호위원회의 [현재 안내서 목록](https://pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=G010030000)에서 적용할 최신 문서를 확인하세요. 이 목록 링크는 위 항목에 대한 법률 자문을 대신하지 않습니다.

## 배포 전 보안 검토

HTTPS·인증 프록시·Secure 쿠키·적절한 네트워크 경계, 병원별 격리와 객체 단위 권한, 세션/초대 링크 만료, 요청량 제한, 서버 입력 검증, 악성 음성 파일 처리와 디코더 격리, 비밀 관리, 의존성·공급망, 로그 내 민감정보, 백업 복구·완전 삭제, 침해 대응과 접근 기록을 검토합니다. 현재 메모리 저장은 실제 의료정보를 안전하게 운영할 수 있다는 증거가 아닙니다. localhost 제한을 풀어 배포하는 것만으로는 준비가 완료되지 않습니다.

공개 배포 승인, 실제 데이터 처리 승인, 외부 AI 공급자 사용 승인, EMR 연동 승인을 서로 구분해 기록하세요. 하나의 승인으로 다른 작업까지 허용한 것으로 처리하지 않습니다.

## 개발 순서

1. **병원 임상 검토:** 책임 수의사가 증상 분류·위험 문구·추가 질문을 검토합니다. 가상 사례의 예상 확인 항목을 구현 결과를 보기 전에 따로 작성합니다. 응급 후보 누락과 사실 변형은 수정 후 다시 평가합니다.
2. **기기 음성 검증:** 보호자 스마트폰과 원내 태블릿에서 한국어·약명·수치·부정 표현을 시험합니다. 인식 미지원이 많으면 로컬 STT와 검토된 외부 STT 중 병원이 운영할 수 있는 방식을 정합니다. 동의 없이 외부 전송하는 대체 경로는 만들지 않습니다.
3. **운영 기반:** 개인별 인증, 환자 식별, 안전한 저장, 문서 버전, 삭제·감사·장애 대응을 구현합니다. 병원 대표번호와 연락 운영 정책을 확정합니다.
4. **제한적 보호자 실증:** 법무·보안·임상 담당자의 승인 후 사전에 정한 범위로 진행합니다. 기존 문진과 병행하고, 수의사 검토 없는 문서 사용을 막습니다.
5. **공식 EMR 연동:** API 접근권·계약·비용·샌드박스를 확인한 뒤 읽기 전용 재진 병력부터 연결합니다. 환자 매칭·출처·갱신시각을 확인한 다음, 별도 검증을 거쳐 승인본 전달을 고려합니다.

## 임상·사용성 평가 계획 (아직 시행하지 않음)

기본 기능 자동 테스트와 실제 임상 유효성 평가는 다릅니다. 수의사가 독립적으로 작성한 시나리오와 예상 병력을 평가 기준으로 사용합니다. 생성된 초안을 정답으로 삼거나 같은 엔진으로 점수를 만들지 않습니다. 정상/비응급만 포함하지 말고, 응급 징후·모름·부정·과거·복합 증상·재진·음성 실패를 포함합니다.

보호자 작성 시간과 이탈·텍스트 전환, 수의사 검토 시간, 중요한 병력의 누락·왜곡, 위험 안내 지연, 승인 후 수정량, 보류 이유를 측정합니다. 기존 문진을 비교 대상으로 삼되 시나리오 순서·학습 효과를 조정합니다. 완료율이나 평균 시간이 좋아져도 임상 안전성이 확보됐다고 결론내리지 않습니다. 파일럿 통과 기준과 사례 수는 병원의 책임 수의사가 평가 전에 정하며, 이번 구현에는 검증되지 않은 성능 수치를 제시하지 않습니다.
