# 센트럴 문진 개발 운영

마일스톤의 목표·이슈·인수 조건·선행 작업은 [초기 이슈 목록](milestones.json)에 정의합니다. 게시 후 진행 상태는 GitHub의 Issues와 Milestones에서 관리합니다.

| 단계 | 사용자에게 보이는 결과 |
| --- | --- |
| M0 | 로컬 Codex가 이슈를 골라 검증 근거가 담긴 PR을 열고, 전용 GCP 환경에서 합성 자료의 저장을 확인합니다. |
| M1 | 레오 보호자가 확인한 답은 되묻지 않습니다. Cloud Run 재시작 후에도 의료진이 승인한 문진을 다시 볼 수 있습니다. |
| M2 | 보호자의 휴대폰에서 제출한 방문을 별도 직원 기기에서 검토합니다. 다른 방문의 자료는 열 수 없습니다. |
| M3 | 승인한 후속 질문과 답변이 최초 문진과 같은 방문에 연결됩니다. |

## 저장소 최초 게시

Mac에서 Juka526의 GitHub CLI 및 Git HTTPS 인증을 확인하고 `bash scripts/bootstrap-github.sh`를 실행합니다. 최초 전달본의 `.handoff/m0.bundle`은 기준선과 기능 브랜치를 복원하기 위한 로컬 파일입니다. 스크립트는 원래 작업 파일을 보존하고, 비공개 저장소에 기준선과 태그를 먼저 게시한 뒤 마일스톤·이슈·초안 PR을 생성합니다. 이미 초기화된 GitHub 저장소에서는 멱등적인 `node scripts/github-setup.mjs`로 누락된 이슈를 등록할 수 있습니다.

## 개발과 검증

Mac에서 GitHub CLI와 Codex CLI에 로그인한 뒤 병합된 main으로 작업합니다.

```sh
npm run harness -- --milestone M1
npm run harness -- --issue 42
```

오케스트레이터가 이슈별 브랜치와 worktree에서 개발, 읽기 전용 독립 검증, 보완, 사용성 개선, 재검증을 진행합니다. 검증이 계속 실패하면 초안 PR에 원인을 남깁니다. 중단된 작업은 같은 명령으로 재개합니다. 사용자가 최종 병합하고, 운영 배포는 main에 포함된 릴리스 태그를 지정해 수동 실행합니다. 테스트에는 가상 자료만 사용합니다.

로컬 서버에서는 메모리 SQLite, 공개 Pages 데모에서는 브라우저 탭 메모리를 사용합니다. 시연 링크에서 보낸 Klat 메시지는 외부 비공개 채널에 저장됩니다. M0의 GCP 저장 검사는 합성 자료 전용이며, 실제 문진 데이터의 영속화는 M1에서 도입합니다.

## 검증 기록

로컬에서 엔진·하네스 상태 전이·Pages 번들·합성 저장 계약 테스트를 실행합니다. 실제 GitHub CI, 브라우저 흐름과 에뮬레이터 결과는 PR의 `CI / verify`에서 확인합니다. Cloud Run 운영 리비전과 Firestore·Storage 실제 왕복 결과는 수동 배포 시 기록합니다. 설정 및 검증 절차는 [Google Cloud 배포](cloud.md)에 있습니다.
